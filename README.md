# Расширение metrika-weekly: все строки «Статистика — сайт»

## Что это

Два **дополнительных** Apps Script файла `SiteMetrics.js` и `SiteWriter.js`, подключаемые **к уже работающему standalone-проекту metrika-weekly**. Ничего в действующих `Config.js`, `ControlReference.js`, `Normalize.js`, `Validate.js`, `MetrikaClient.js`, `SheetWriter.js`, `Main.js` менять не нужно. Исходный архив проекта от 25.10 более ранний, чем последние локальные исправления Cursor, поэтому **не заменяйте текущий проект содержимым старого архива**.

Назначение — добавить к проверенному общему трафику остальные показатели **именно вкладки «Статистика  - сайт»**, а не всех 19 листов книги. Отдельный запуск не изменяет старый `metrika_weekly`: новые данные поступают в `metrika_site_weekly`, видимые в привычной структуре — в `site_report_preview`. Оба листа создаются только в уже заданной **отдельной тестовой таблице** `TARGET_SPREADSHEET_ID`. ID рабочей книги остаётся запрещённым через `assertSpreadsheetIdAllowed`.

## Добавляемые показатели

- Android, iOS (только на mobile+tablet): уникальные посетители, новые посетители, визиты; отдельные доли Android/iOS.
- Mobile+tablet: уникальные посетители за весь период без суммирования уникальных групп, новые посетители и визиты.
- Источники Organic, Direct, Referral, Social: недельные уникальные посетители с атрибуцией **last**. Сумма не считается общими уникальными.
- 10 выбранных путей из строк 34–43: просмотры **хитов** `ym:pv:pageviews` с фильтром по точному URLPath. Для `/radio/stations/?st=rr` используем `URLPathFull`, чтобы учесть `?st=rr`.
- Основная посещаемость — тот же исходный набор из `metrika_weekly` и тот же API. Повторный API-запрос при отдельном импорте не изменяет исходную строку `metrika_weekly`.
- Представление включает строки 1–50 в порядке основного листа, одну пару колонок «значение / изменение» на каждую неделю, а также вычисляемые доли и формат времени `ч:мм:сс`.

**Отличия от исторической методики:** новые пользователи берутся напрямую из API, а не из старых ручных процентов. Desktop (строка 46) — остаточная доля `(все − mobile+tablet)/все`, как в старой формуле; это не отдельные уникальные посетители десктопов. Доля Android/iOS считается в базе `(Android+ iOS)` для повторения формулы; эти группы не обязаны полностью покрывать мобильную аудиторию. Если встречены другие мобильные ОС, preview выдаст предупреждение. Доли различаются по знаменателю. Историческая система не подтверждает фильтры и атрибуцию источников — перед признанием полной сопоставимости проверьте живые результаты двух недель и исходный отчёт Метрики.

## Порядок первого безопасного запуска

1. В Cursor сохраните текущие 36 тестов и актуальные исправления. Добавьте **только** два файла в `metrika-weekly/src/`; тесты расширения — отдельно в `tests/` (при желании).
2. Запустите `node --test` по вашему полному актуальному проекту и отдельно тесты расширения.
3. Добавьте в редактор standalone Google Apps Script только `SiteMetrics.js` и `SiteWriter.js`. Не меняйте ключи, `METRIKA_TOKEN`, `TARGET_SPREADSHEET_ID`, права проекта, `Main.js` и существующие листы. Никаких триггеров и расписаний.
4. Проверьте, что `TARGET_SPREADSHEET_ID` — **тестовая** книга. Запустите `previewSiteControlWeek`. Он обращается к API, но не открывает Google Sheets и ничего не записывает. Первая проверка особенно важна для групп ОС, источников и фильтра `URLPathFull`.
5. Если preview успешен, отдельно запустите `importSiteControlWeek`. Сверьте две новые вкладки `metrika_site_weekly` и `site_report_preview` в тестовой книге. При повторном вызове строка той же недели обновляется, новая не создаётся.
6. Следующий период: задайте `START_DATE=2026-09-28` и `END_DATE=2026-10-04` в Script Properties; сначала `previewSiteConfiguredWeek`, затем `importSiteConfiguredWeek`. Потом отдельно 05.10–11.10. Новые недели сортируются по дате, без дубликатов; изменения рассчитываются только для непосредственно соседних календарных недель.

Все функции запускаются **вручную**. Не запускать импорт, пока preview не подтвердит полноту.

## Важные ограничения

- Проверены **локальные mock-тесты**, но **живой ответ Метрики для новых срезов не доступен в этой среде**. Не утверждаем, что API подтвердил конкретный состав мобильных ОС и все фильтры.
- Ошибка любого из 14 запросов останавливает публикацию. Не подменяем отсутствие показателей нулём. Источники, отсутствующие в полностью полученном grouped-ответе, интерпретируются как нулевые только после проверки полноты и корректности самого отчёта.
- Согласование устройства/ОС, атрибуции источников и URL `?st=rr` с историческими отчётами — отдельная приёмка. По умолчанию для групп используется `operatingSystemRoot`, для источников `trafficSource` и `attribution=last`, для URL применяется точное равенство. Это **новая версия определений** `metrika_site_weekly_v1`.
- У скрипта нет транзакционного отката: при ошибке между записью нормализованной строки и перестроением представления первая может уже быть записана. Повторный импорт безопасен по ключу. `flush` вызывается после записи и до `releaseLock`.
- При создании новых листов/форматировании изменение могло произойти и при последующем сбое. В рабочую таблицу не пишет.
- Никаких секретов в исходном коде, URL, отчётах, журналах или документах.
- Если название `site_report_preview` уже занято пользовательским листом, скрипт остановится, а не перепишет его. Владение представлением подтверждается служебным маркером в скрытой строке 52.
